# 얼굴 피부 보정

Status: 구현 계약, 미구현. 기기 내 처리 우선, 필요 시 별도 모델 서버.
Related: [pipeline](skin_retouch_pipeline.md), [validation](skin_retouch_validation.md)

## 1. 기능

Evoto는 사용 경험의 참고이며 내부 알고리즘/품질 동등성이 확인됐다는 뜻은 아니다.

| 이름 | ID | 보정 대상 | 보존 대상 |
|---|---|---|---|
| 잡티·여드름 제거 | Blemish | 국소 잡티, 여드름 붉은 점과 작은 피부 불균일 | 점·주근깨, 모공, 정상 피부, 눈썹, 머리카락 |
| 유분광 제거 | Shine | 이마/코/볼의 과도한 번들거림 | 입체감, 정상 하이라이트, 눈 반사광, 피부톤 |
| 다크서클 완화 | DarkCircles | 눈 아래 피부의 어두운 색조 | 눈/속눈썹/아이라인, 눈 밑 형태와 정상 음영 |
| 면도자국 완화 | ShavingShadow | 인중/턱/턱선의 짧은 수염 자국과 푸른 색조 | 입술, 윤곽, 기른 수염/콧수염, 피부 질감 |

잡티/여드름은 중복 메뉴를 만들지 않는다. 점·주근깨와 여드름 구별이 불확실하면 보존한다. 면도자국은 수염 전체 제거가 아니다. 주름/미백/전체 스무딩/얼굴형/눈/치아/몸 피부/수동 브러시/일괄 처리는 범위 밖이다.

네 항목은 최종 제품 계약이며 단일 모델이 네 항목을 제공한다는 뜻이 아니다. 첫 실험은 MI-GAN의 잡티·여드름 복원과 별도 자동 검출이다. 유분광/다크서클/면도자국은 각 경로를 검증한다. 개발 중 미완료 항목은 미지원 상태로 표시하고 활성화하지 않으며 일부 구현을 전체 완료로 보고하지 않는다. 제품 UI에는 모델 이름 대신 처리 위치와 사용 가능 여부를 표시한다.

## 2. 메뉴

Tool.SkinRetouch, label 피부 보정. 기존 Material Rounded 아이콘과 토큰을 사용한다.

| Profile | Root | AI |
|---|---|---|
| General | 라이트, 색상, 혼합, 자르기, 디테일, AI | 뒤로, 피부 보정, 선택, 지우기, 채우기, 확대, 스타일, 자동, 지시 |
| Portrait | 피부 보정, 자동, 디테일, 라이트, 색상, 혼합, 자르기, AI | 뒤로, 선택, 지우기, 채우기, 확대, 스타일, 지시 |

이 표는 tool_groups.md와 T79의 이전 목록에 대한 추가 변경이다. 2단계 구조/profile별 중복 없는 노출을 유지한다. Unknown에서도 일반 메뉴로 진입할 수 있다. 메뉴 감지 결과를 보정 가능성으로 쓰지 않으며 뒤늦은 메뉴 감지가 열린 시트/선택 얼굴을 바꾸지 않는다.

## 3. 얼굴 선택

- 현재 편집 기반에서 로컬 분석한다. source 메뉴 감지 좌표는 사용하지 않는다.
- 하나면 자동 선택, 여러 개면 보정 가능한 가장 큰 얼굴이 기본이다. 동률은 위쪽/왼쪽 순서. 썸네일 목록으로 다른 얼굴을 선택한다.
- 한 세션은 한 얼굴이다. 얼굴 변경은 요청/후보를 폐기하고 네 값을 0으로 초기화한다. 적용 후 다른 얼굴을 보정할 수 있다.
- crop으로 완전히 제외된 얼굴은 목록에서 뺀다. 일부만 보이면 필요한 부위가 충분한 항목만 지원한다.
- 모델 미준비/분석 실패와 얼굴 0개를 구분한다. 작은 얼굴/가림/심한 옆얼굴/landmark 누락은 항목별 비활성과 짧은 사유로 처리한다. face rectangle 전체를 피부로 간주하지 않는다.

## 4. 시트와 강도

EditSheet/AdjustSlider를 재사용한다. 제목, 얼굴 선택, 필요한 처리 위치 표시, 네 slider, 미리보기, 고정 취소/적용 행을 둔다. 내부만 scroll하고 최대 높이 45%, 캔버스 최소 절반을 지킨다.

- 정수 0..100, 기본 0, 내부 0..1. 더블 탭 초기값 복귀/접근성 조절을 지원한다.
- 100은 질감 보존 기준을 통과한 최대 보정이며 얼굴 재생성/평탄화가 아니다.
- 강도는 준비된 종류별 후보와 원본의 로컬 합성이다. StyleRetoucher의 내부 특징 제어를 재현한다고 주장하지 않는다. 한 번의 전체 얼굴 보정 결과를 네 슬라이더에 공유해 독립 제어처럼 표시하지 않는다.
- 명시적 미리보기는 0보다 큰 항목 중 후보가 없는 항목만 준비한다. 후보가 있으면 재추론하지 않는다.
- 준비된 강도 변경은 로컬 합성이다. 새 항목의 후보가 없으면 이전 미리보기를 유지하되 Apply를 비활성화하고 갱신 필요 상태를 표시한다.
- 모두 0이면 진입 모습과 동일하며 Apply/미리보기는 비활성이다. 변화 없는 결과도 history를 만들지 않는다.
- 미리보기는 기존 조정/crop을 포함한다. 공통 hold-to-compare는 프로젝트 원본이며 별도 제스처를 추가하지 않는다.
- Apply는 준비된 결과를 저장/commit하며 새 추론을 하지 않는다. 필요한 후보와 로컬 render가 모두 준비돼야 활성이다.
- 적용 후 재진입은 현재 문서 위 새 세션이고 값은 0이다. 이전 적용값 재편집은 범위 밖이며 Undo로 되돌린다.

## 5. 상태

| 상태 | 행동 |
|---|---|
| 분석 중 | 진행 표시, 취소 가능, Apply 비활성 |
| 얼굴 없음 | 보정할 얼굴을 찾지 못했어요, 문서 유지 |
| 모델 미준비/분석 실패 | 얼굴 분석을 준비하지 못했어요, 명시적 재시도 |
| 준비/값 0 | 값 변경 가능, 처리 없음 |
| 보정 중 | 기존 progress overlay, 피부를 보정하는 중, 취소 가능 |
| 결과 준비 | 로컬 강도 미리보기, Apply 활성 |
| 변화 없음 | 보정할 부분을 찾지 못했어요, 해당 후보 no-op |
| 서버 미설정/연결 실패 | 기존 settings/snackbar 패턴, 자동 전환 없음 |
| 처리/저장 실패 | 오류 snackbar, 값 유지, 명시적 재시도 |

처리 중 얼굴/설정/강도는 잠그고 취소/Back은 가능하다. 취소/Back/dismiss는 draft/요청을 버리고 진입 문서를 유지한다. Undo/Redo/Reset 등 문서 변경 시 draft를 무효화하고 닫는다. draft가 열려 있으면 export는 비활성이다. 실패 시 성공한 일부 항목만 자동 적용하지 않는다.

문자열은 한국어 strings.xml에 둔다. 썸네일 선택 상태, icon contentDescription, slider 값 읽기, 48dp 터치 영역을 제공한다. 서버 모드에는 보정 서버 표시와 설정 주소 확인 경로를 둔다. 로컬에 서버 API 키를 요구하지 않는다.

## 6. 실행 위치

기기 내 처리를 우선 검증하고 필요하면 별도 모델 서버를 사용한다. Gemini/외부 범용 생성 API는 이번 backend가 아니다.

로컬 사진 업로드는 0건이다. 모델 다운로드는 사진 업로드와 구분하고 준비 상태로 다룬다. 로컬 오류/메모리 부족으로 서버에 자동 전송하지 않는다. 서버는 명시적으로 설정하고 선택 얼굴 최소 ROI만 전송한다. 이미지 전송은 미리보기 실행 시에만 가능하다.
